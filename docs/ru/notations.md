# Нотации: EPC, DFD, IDEF0

Три нотации бизнес- и системного анализа поставляются наборами типов узлов:
EPC (событийные цепочки процессов), DFD (диаграммы потоков данных) и IDEF0
(функциональные модели). Каждый набор несёт свою палитру и направление, в
котором такие диаграммы обычно рисуют.

```vue
<script setup lang="ts">
import { NOTATIONS, notationRegistry } from '@dskripchenko/flow'
import { FlowEditor } from '@dskripchenko/flow/vue'

const notation = NOTATIONS.epc
</script>

<template>
  <FlowEditor v-model="graph" :registry="notationRegistry('epc')" :palette="notation.palette" />
</template>
```

`FlowView` принимает тот же `registry`. `meta.direction` графа можно брать из
`notation.direction`.

## EPC

| Тип             | Фигура                                    |
| --------------- | ----------------------------------------- |
| `epc-event`     | Шестиугольник                             |
| `epc-function`  | Скруглённый блок                          |
| `epc-and`, `epc-or`, `epc-xor` | Кружок-оператор с ∧, ∨ или × |
| `epc-org`       | Эллипс (организационная единица)          |
| `epc-info`      | Блок (информационный объект)              |
| `epc-document`  | Документ                                  |
| `epc-system`    | Блок со значком компьютера                |
| `epc-path`      | Шестиугольник со ссылкой на процесс       |

Организационные единицы, системы и документы присоединяются к функциям
связями-ассоциациями (`kind: 'association'`). EPC идёт сверху вниз.

## DFD

| Тип           | Фигура                                                        |
| ------------- | ------------------------------------------------------------- |
| `dfd-process` | Эллипс с номером сверху; раскрывается в нижний уровень        |
| `dfd-entity`  | Блок со второй рамкой (внешняя сущность)                      |
| `dfd-store`   | Хранилище, открытое справа, с номером в отдельной ячейке      |

Связи — потоки данных; их подписи называют данные. Номера берутся из
`data.number` (`1`, `1.2`, `D1`).

## IDEF0

| Тип              | Фигура                                                                |
| ---------------- | --------------------------------------------------------------------- |
| `idef0-function` | Блок с номером в правом нижнем углу (`A0`, `A1`…), раскрывается       |
| `idef0-boundary` | Капсула: конец стрелки на границе диаграммы                           |

У функционального блока четыре порта IDEF0 (`IDEF0_PORTS`): `input` слева,
`control` сверху, `output` справа и `mechanism` снизу. Связь указывает, в
какой порт она входит (`toPort: 'control'`).

Раскладка ставит узел, который только питает порт сверху или снизу другого
узла (или только забирает из него), над или под этим узлом, а не в поток, —
поэтому управление оказывается над блоком, а механизмы под ним, как принято в
IDEF0. Правило действует для любого типа с такими портами, не только для IDEF0.
