# Интеграция с хостом

Что реализует бэкенд (или админ-панель вроде laravel-admin), чтобы показывать,
отслеживать и редактировать процессы. Все данные — JSON.

## Модель

Хранится как есть: `GET` её возвращает, `v-model` / `change` редактора её
выдают. Схема: `@dskripchenko/flow/schema/graph.schema.json` (JSON Schema
2020-12). На сервере проверяйте любым валидатором JSON Schema, затем
применяйте смысловые проверки `validateGraph` (те же правила можно
реализовать на сервере: уникальные идентификаторы, переходы между
существующими узлами, порты нужного вида).

Позиции необязательны. Процесс, созданный на сервере без позиций,
раскладывается на клиенте; первая правка в редакторе сохраняет позиции.

## Снимок мониторинга

`GET /…/state` → снимок
(`@dskripchenko/flow/schema/snapshot.schema.json`):

```json
{
  "nodes": { "<nodeId>": { "status": "active|done|error|waiting|skipped|<custom>", "count": 3, "badge": 2, "message": "…", "updatedAt": "ISO or ms" } },
  "edges": { "<edgeId>": { "count": 10, "traversed": true } },
  "path": ["<nodeId>", "…"],
  "current": ["<nodeId>"],
  "updatedAt": "ISO or ms"
}
```

- Для одного экземпляра: статусы по его истории, `path` и `current`.
- Для обзора процесса: `count` по узлам и переходам (сколько экземпляров в
  каждом состоянии), `status: "error"` и `badge` там, где что-то падает.
- При провале в подпроцесс просмотр передаёт `context.path` (идентификаторы
  узлов подпроцессов, в которые вошли) и `context.ref` (ссылку подпроцесса);
  возвращайте состояние для этого уровня. На ошибки отвечайте статусом не
  2xx: просмотр покажет ошибку, сохранит последние данные и увеличит паузу
  между запросами.
- Первый снимок, отрисованный сервером, передавайте в `state`; при заданном
  `poll` опрошенные снимки его заменяют — до первого запроса нет пустоты.
- Параметры хоста (экземпляр на экране, фильтр) — в `pollParams`; они
  приходят в `fetch` как `context.params`, а их изменение сразу перезапускает
  опрос (старые данные сбрасываются, если вместе с изменением не пришёл новый
  `state`). Открытый метод `refresh()` опрашивает немедленно.

## Переключение

Просмотр вызывает `persistToggle(change)` один раз на переключение; отправьте это на сервер:

```json
{ "kind": "node", "id": "cancelled", "enabled": false, "path": [] }
```

`path` — идентификаторы узлов подпроцессов от корня (на корне пусто).
Откажите (статус не 2xx, исключение в `persistToggle`), чтобы откатить
переключатель; сообщение об ошибке покажется в тосте. Затем передайте
обновлённую модель в `graph` (или оставьте как есть: оптимистичное состояние
держится, пока `graph` не изменится).

`onToggle` — устаревшее имя `persistToggle` (до 1.1): оно тоже вызывается один
раз, но используйте `persistToggle` — `onToggle` это обработчик события
`toggle`, которое приходит после завершения функции сохранения.

## Подпроцессы

`node.subgraph` — либо встроенный граф, либо строковая ссылка. Для ссылок
передайте `subgraphs: { ref: Graph }` или
`loadSubgraph(ref, node) => Promise<Graph>` (например, `GET /processes/{ref}`).

## Редактирование

`FlowEditor` отправляет `change` с данными:

```ts
{
  command: Command        // на корне: воспроизводится через applyCommand(rootGraph, command)
  local: { command, path } // как сделано, внутри подпроцесса по пути `path`
  description: string     // "add task-1", "move 3 nodes", …
  graph: Graph            // вся модель после изменения
  source: 'edit' | 'undo' | 'redo'
}
```

Простейший бэкенд сохраняет `graph` (с debounce). Бэкенд с совместной
работой или аудитом сохраняет `command`. Заблокированные типы узлов
(проп редактора `locked: ['тип', …]` или `locked: true` в реестре) нельзя
двигать, изменять или удалять в редакторе —
обеспечьте то же на сервере.
