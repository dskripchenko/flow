# @dskripchenko/flow — дизайн

Пакет показывает, мониторит и редактирует графы процессов и машин состояний:
статусы и переходы (циклы разрешены), текущее состояние запущенных экземпляров,
включение/отключение элементов, проваливание в подпроцессы. Ядро — чистый
TypeScript без зависимостей и без DOM; Vue-компоненты строятся поверх
`@dskripchenko/ui`. Пакет закрывает этапы 1 (просмотр), 2 (мониторинг),
3 (редактор) и 5 (полировка); этап 4 (интеграция в ядро laravel-admin) делает
автор в репозитории ядра — контракт для него в `docs/en/integration.md`.

## Решения

- Три точки входа:
  - `@dskripchenko/flow` — ядро (модель, валидация, раскладка, мониторинг,
    поллер, команды редактирования, математика вьюпорта);
  - `@dskripchenko/flow/vue` — `FlowView`, `FlowEditor`, `FlowCanvas`,
    `mountFlow`/`mountFlowEditor`; peer `vue` и `@dskripchenko/ui`;
  - `@dskripchenko/flow/mermaid` — `fromMermaid()`; peer
    `@dskripchenko/diagrams`. Отдельная точка, чтобы ядро осталось без
    зависимостей и чтобы `parse()` из diagrams (он тянет все рендереры
    диаграмм) не попадал в бандл тех, кому импорт не нужен.
- Все три peer-зависимости опциональны; `dependencies` пусты (CI проверяет).
- Standalone-сборка (`DskFlow`, IIFE) — как у openapi: Vue, кит, стили и
  парсер Mermaid внутри, CSS вставляется скриптом.
- Модель — JSON с `version: 1`; `position` — центр узла (размер зависит от
  типа и подписи, центр стабилен при смене подписи). Id уникальны во всём
  графе (узлы, рёбра, группы) — одна выборка, одно пространство имён.
- Мониторинг хранится отдельно от модели и сводится чистым редьюсером.

## Переиспользование @dskripchenko/diagrams

**Раскладка.** `@dskripchenko/diagrams@1.1.0` публично экспортирует только
`render`, `parse`, `detect`, измерители и `THEME_VARIABLES`; слоистая
раскладка (`src/layout/layered`) наружу не выходит. Поэтому она скопирована в
`src/layout/layered/` без изменений, кроме путей импорта (`errors.ts` и
`geometry.ts` — минимальные копии `Box`/`Point`/`DiagramError`/`tooLarge`).
Код раскладки скрыт за `layoutGraph()`; остальной пакет его не видит.

Что нужно экспортировать из diagrams, чтобы убрать копию:

- подпуть `@dskripchenko/diagrams/layout` (отдельный entry, без рендереров):
  `layout(input: LayoutInput): LayoutResult`, `MAX_NODES`, `MAX_EDGES`;
- типы `LayoutInput`, `LayoutNode`, `LayoutEdge`, `LayoutCluster`,
  `LayoutResult`, `EdgeRoute`, `Direction`, `Box`, `Point`;
- `DiagramError` уже экспортирован.

После этого `src/layout/layered/` удаляется, а `src/layout/index.ts`
импортирует `layout` из подпути — интерфейс (`layoutGraph`) не меняется.

**Парсер.** `parse(source): unknown` публичен, но типы AST не экспортированы.
`src/mermaid/index.ts` описывает нужную часть AST (`StateDiagram`,
`Flowchart`) локально и проверяет `type`/`Map` в рантайме. Чего не хватает:

- экспорт типов `StateDiagram`, `StateNode`, `StateComposite`,
  `StateTransition`, `StateNote`, `Flowchart`, `FlowNode`, `FlowEdge`,
  `FlowSubgraph`, `ShapeKind`;
- отдельные `parseState` / `parseFlowchart` (лучше подпутём
  `@dskripchenko/diagrams/parse`), чтобы импорт Mermaid не тянул рендереры
  всех 11 типов диаграмм.

Семантика импорта: составное состояние → узел `subprocess` со встроенным
`subgraph` (переходы, пересекающие границу, поднимаются до составного узла);
параллельные регионы → группы; `[*]` → `start`/`end` с id `start`/`end` (или
`<composite>-start`); заметки → `note` + ребро `association`. Во flowchart:
ромб/шестиугольник → `decision`, `[[…]]` → `subprocess`, `((…))` без входов →
`start`, `(((…)))` → `end`, подграфы → группы.

## Раскладка

- Узлы без `position` раскладывает слоистая раскладка (циклы, кластеры-группы,
  место под подписи рёбер — средний ранг каждого ребра). `transpose: true` —
  меньше пересечений.
- Смешанный случай: зафиксированные узлы остаются на месте, остальные
  берутся из раскладки со средним сдвигом к зафиксированным и сдвигаются по
  поперечной оси до отсутствия наложений. Изгибы раскладки в этом случае
  отбрасываются, рёбра идут напрямую между портами.
- Все узлы с позициями — раскладка не запускается, только трассировка рёбер
  (дёшево; редактор после первой правки всегда в этом режиме).
- Сплайн через изгибы раскладки: концы обрезаются по реальному контуру
  (прямоугольник/эллипс/ромб) в сторону первого/последнего изгиба, кривая —
  равномерный B-сплайн (как в diagrams/Mermaid). Без изгибов — bezier между
  якорями на сторонах (как n8n). Ортогональная трассировка — колена по
  изгибам, почти-соосные изгибы (< 3 px) выравниваются.
- Направление: `meta.direction`, иначе `auto` — компонент выбирает LR для
  альбомного холста и TB для портретного (решается один раз при монтировании).

## Рендер и взаимодействие

- `FlowCanvas` — общая SVG-поверхность для просмотра и редактора; модель не
  хранит, всё — события. Порядок слоёв: группы, линии рёбер, узлы, подписи
  рёбер (выше узлов, они же — фокусируемые элементы рёбер), слой редактора.
- Производительность (500 узлов): обновления вьюпорта и pointermove
  батчатся в rAF; при перетаскивании пересчитываются только рёбра
  перетаскиваемых узлов (`routeEdges(..., only)`); неизменённые геометрии узлов
  сохраняют идентичность, поэтому дочерние `FlowNodeShape` не
  перерисовываются. Замер в browser-check: медиана ~16.7 мс на кадр при
  панорамировании и при перетаскивании узла в графе из 500 узлов.
- Выбор в просмотрщике — по «тапу» (отпустили без движения): панорамирование
  или щипок, начатые над узлом, не открывают панель. Захват указателя
  откладывается до начала движения, иначе Chrome перенаправляет
  click/dblclick на холст. Для узлов с подпроцессом выбор ждёт 230 мс, чтобы
  двойной клик открыл подпроцесс, а не панель.
- Первый вид: если «вписать целиком» даёт масштаб < 0.62 (подписи не
  читаются), вид открывается в читаемом масштабе от начала процесса или на
  текущем шаге экземпляра (с прижатием начала потока к краю). Кнопка «вписать»
  всегда показывает всё. Первое появление `current` в мониторинге подводит вид
  к нему, пока пользователь сам не двигал вид.
- Клавиатура: все узлы — `role="button"`, `tabindex=0`; стрелки — к
  ближайшему узлу в направлении; Enter/Space — выбор и детали; Escape —
  закрыть панель → снять выбор → подняться из подпроцесса; `+`/`-`/`0`.
- Тач: один палец — панорама, два — щипок, долгое нажатие — контекстное меню.

## Редактор (этап 3)

Реализован; ниже — архитектура, на которую он опирается.

- **Команды.** Любая правка — `Command` (addNodes, removeElements,
  updateNode/Edge/Group с патчем, где `null` удаляет поле, moveNodes, addEdge,
  setEnabled, addGroup, updateMeta, replace, batch), применяемая чистой
  `applyCommand`. Хост получает команду в событии `change` и может её
  переиграть, логировать или отправить на сервер.
- **История.** `History` хранит пары до/после (графы неизменяемы и делят
  неизменённые узлы — дёшево, и отмена не зависит от правильности обратных
  команд). Подряд идущие команды с одинаковым `mergeKey` в окне 800 мс
  сливаются (набор подписи, сдвиг стрелками). `reset` при внешней смене
  модели. Важно: `v-model` на глубоком `ref` возвращает прокси — сравнение и
  хранение через `toRaw`.
- **Подпроцессы.** Встроенный подпроцесс редактируется на месте:
  навигационный путь `path`; команда уровня оборачивается в `updateNode`
  узла-подпроцесса на корне (`atRoot`), событие несёт и корневую, и локальную
  команду.
- **Фиксация позиций.** Первая правка автоматически разложенного уровня
  добавляет в тот же шаг `moveNodes` для всех узлов без позиций — ничего не
  прыгает, отмена возвращает исходную модель.
- **Палитра.** Перетаскивание с «призраком» (pointer events, не HTML5 DnD —
  работает на таче) или клик/Enter — узел в центре вида со сдвигом от занятых
  мест. Двойной клик по фону — состояние; контекстное меню — «добавить сюда».
- **Порты и соединение.** Ручки на сторонах (или на портах типа) у
  наведённого/выбранного узла; при протягивании превью-кривая прилипает к
  ближайшей ручке в радиусе 28 px экрана; учитываются `noIncoming`,
  `noOutgoing`, `kind` портов. Новое ребро выделяется — сразу подписать.
  Концы выделенного ребра перетаскиваются (переподключение), бросок в пустоту
  удаляет ребро. С клавиатуры — «Добавить переход в…» в свойствах узла.
- **Выделение.** Клик, Shift/Ctrl/⌘ — добавить, Shift+протяжка по фону —
  рамка, Ctrl+A. Выравнивание/распределение — из панели свойств и меню.
- **Валидация.** `validateGraph` на каждую правку уровня; маркеры на узлах и
  цвет рёбер; вкладка «Проблемы» с переходом к элементу; событие `validate`.
- **Блокировка.** `locked: true` в типе — узел нельзя двигать, менять,
  удалять (поля панели отключены, пояснение кита `UidAlert`).
- **Импорт/экспорт.** JSON (скачивание файла + событие `export`), импорт JSON
  и Mermaid через `UidModal` (Mermaid — только если хост передал `mermaid`).
  Импорт — команда `replace`, отменяемая.
- **Узкий экран** (< 760 px): палитра и свойства уезжают в `UidDrawer`,
  кнопки в тулбаре.

### Что можно добавить дальше

- Создание/редактирование групп в UI (модель, команды, раскладка и выбор
  группы в свойствах есть; нет кнопки «сгруппировать выделенное»).
- Ручные изгибы рёбер (waypoints в модели ребра) и их редактирование.
- Редактирование подписи прямо на холсте (сейчас — фокус на поле в панели по
  двойному клику / Enter).
- Вставка из системного буфера между вкладками (копирование пишет JSON в
  буфер, вставка пока из внутреннего).
- Совместное редактирование поверх команд (команды уже сериализуемы).

## Кит (@dskripchenko/ui): найденное

Обходные решения здесь временные; по правилу «чиним в источнике» — в кит:

- `UidMenu` открывается только кликом по триггеру — нет управляемого режима
  (`v-model:open`) и контекстного режима «в точке». Контекстное меню сейчас:
  невидимый триггер 1×1 в точке + программный click (`editor/FlowContextMenu.vue`).
- `UidTooltip` теряет якорь (всплывает в левом верхнем углу), если
  содержимое триггера перерисовывается — например, у `UidButton` меняется
  `variant`. Обход: кнопки-переключатели держат один `variant`, нажатое
  состояние рисуется классом `.fl-toggle.is-active`.
- `UidBadge` с `dot` скрывает содержимое (так задумано, но легко ошибиться —
  дважды попались на этом).
- `useLocale()` без провайдера отдаёт `ru` — компоненты пакета всегда
  оборачиваются в `UidLocaleProvider` (en/ru по `locale`), поэтому корень —
  фрагмент, и атрибуты (`class`, `style`) пробрасываются вручную
  (`inheritAttrs: false` + `v-bind="$attrs"`).
- Тосты требуют `UidToastProvider`; компоненты монтируют свой
  (`toastProvider`, по умолчанию `true`; отключить, если в приложении уже есть).

## Ограничения

- `MAX_NODES = 500`, `MAX_EDGES = 2000` — предел раскладки (как в diagrams);
  больший граф с позициями рисуется, но автораскладка бросит ошибку.
- Подписи узлов — до 3 строк, рёбер — до 2, с многоточием.
- Колесо по умолчанию масштабирует (`wheel: 'pan'` — прокручивает); на
  странице с прокруткой холст перехватывает колесо, когда под курсором.
